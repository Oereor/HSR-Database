# 排轴模拟器 Phase 1 实施与验收

日期：2026-10-11。本文记录本轮本地实现及其验收结果，后续维护以实际代码和现行架构规范为准。

## 交付范围与访问

已实现「游戏工具 / Game Tools」导航、工具目录和排轴模拟器。中文路由为 `/game-tools/`、`/game-tools/action-planner/`；英文对应 `/en/game-tools/`、`/en/game-tools/action-planner/`，均遵循尾斜杠约定。

按本次用户确认，首版仅支持单波次，不加入方案保存。四个友方槽位初始为空，支持真实角色或手动单位；敌人默认不启用，最多添加四个，可编辑名称、速度和站位顺序。面板速度须独立填写；选择角色、修改基础速度不会覆盖已有面板速度。

在仓库目录执行 `pnpm dev`，默认访问 `http://127.0.0.1:4174/game-tools/action-planner/`。已构建站点可执行 `pnpm preview --host 127.0.0.1 --port 4173`，访问同路径。设置 `PUBLIC_SITE_URL` 时与实际本地 origin 保持一致。

## 代码与数据边界

- `src/lib/action-planner/`：纯 TypeScript 类型、数学、验证、排序、状态转换和表单 Preset。`types.ts` 定义计划、单位、目标、事件、独立速度实例、行动记录、快照和诊断接口。
- `src/lib/server/action-planner.ts`：服务器专用轻量投影；`src/routes/game-tools/`：预渲染页面和工具入口。
- `src/lib/components/action-planner/`：单位配置、未来记录、队列步进及有序效果编辑。站点文案为成对 Paraglide 消息，调用显式使用页面 locale。
- 共享路由生成加入两条 locale-neutral 路径，沿用 schema 53；`data:ensure` 检测旧清单缺失工具路由时使缓存失效，重新生成。sitemap、英文页面和静态验证消费同一清单。
- 导航复用已有资源管线，映射 `SettingsHotkeysIcon` 为 `game-tools`。角色图片继续使用现有 resolver 和 `AssetImage` 的缺失/加载失败 fallback。

服务端读取本语言生成角色目录和详情，只返回 `id`、`name`、`avatarId`、可选 `baseSpeed`。基础速度来自真实 `Character.baseStats.fixed.speed`。本次两种语言各有 98 个可选角色，速度字段均有效；两种语言的身份、基础速度、头像标识一致。缺失字段、非正速度或单个详情不可读取时，保留角色选项并要求手填基础速度，不编造数据、不跨语言回退。

浏览器不接收完整角色详情、敌人目录、技能、TextMap 或装备目录。Preset 名称从对应语言目录提取三个条目：翁瓦克 `308`、风套 `110`、舞舞舞 `21018`；这些 ID 仅用于 UI。角色和装备的原始解析管线未改变。

## 数学、排序与事件接口

引擎公开 `createInitialState`、`stepSimulation`、`simulatePlan`，以及队列读取、编辑器预览和验证函数。状态转换克隆输入，不修改计划或前序快照；每次推演重新初始化状态和插队序号。

满行动条为 `10000`，剩余 AV 为 `remainingAG / effectiveSPD`。有效速度为面板 SPD 加所有固定修正、所有基于当前自定义基础速度的百分比修正。内部不舍入 AV；显示保留至多三位小数。自然推进只清除浮点消减中的机器精度残差，不使用伪负 AV 排序。延后可超过满行动条。

`advance` 减去满行动条的指定百分比，最低为零；`delay` 增加同样基准的比例；`immediatelyAct` 直接置零。因此 AG 为 25000 时，100% 提前后仍为 15000，立即行动则为零。

每条即时操作先读取作用前的待行动队列，再按该队列顺序形成目标批次。整批到零时保持批内顺序，新批次优先于旧零 AG 批次。已为零的待行动者再次受到非零提前仍刷新优先级；0% 提前不刷新。自然平局使用友方优先、阵营内站位次序和稳定 ID 兜底。行动者在结算中退出待行动队列，对其施加行动条操作产生明确提示，不形成下一自然回合的提前；速度效果仍正常施加或解除。

自然行动严格按以下顺序结算：

1. 消耗最小剩余 AV，按各单位当前速度扣除对应 AG。
2. 标记行动者，快照其已有速度实例。
3. 在回合结束前按用户操作列表顺序应用效果。
4. 正常回合结束，仅递减快照中仍有效的实例，移除到期实例。
5. 使用更新后的有效速度，将行动者以完整 AG 重新入队。

未行动单位改变速度时保留其剩余 AG。速度实例 ID 由添加操作 ID 和目标单位 ID 派生；群体添加为每个目标产生独立实例。解除操作指定唯一实例；同名实例不自动覆盖或刷新。先解除旧实例再新增表示刷新，新实例不会被旧回合快照递减。编辑器用同一个 `applyOperations` 预览前序操作，所以同节点刚添加的实例也可被后续操作解除。

事件仅绑定战斗开始，或 `{ kind: 'action', unitId, turn }`，不绑定行号或累计 AV。普通速度/名称修改保留单位 ID；更换角色、清空后重建单位使用新 ID。不可达事件保留在独立列表并允许编辑、删除，不会改绑到替代单位。改变早期事件后，从初始状态确定性重算。

参数错误显式报错；有效速度为零、负数或非有限计算会停止推演，只发布已完整结束的行动及对应快照。显式目标集合中有缺失单位时整条操作跳过并提示；解除列表中有缺失/到期实例时整条解除跳过并提示，不猜测替代目标。

默认上限为 60 次行动或累计 600 AV，先达到者终止；可配置的硬边界为 500 次行动、100000 AV。零 AV 行动也计入行动次数，防止无耗时行动链使页面卡住。

## 交互与 Preset

桌面为左侧单位配置、右侧纵向行动列表及编辑器；中等宽度把编辑器移到列表下方，窄屏全部纵向排列。使用本站颜色、圆角、边框和表单模式，没有复制独立 HTML 的模拟代码或样式。

未来视图显示重复自然行动、累计 AV、本次推进 AV、行动时速度和节点效果数。队列视图读取同一推演的初始/回合结束快照，每个单位只有下一回合，提供前后步进、有效速度、剩余 AV 和可展开的速度实例。队列步进会选中刚完成的行动，编辑其回合结束前效果后重新推演；该编辑器窗口不是队列快照中的回合结束后窗口。

效果表单提供单体、多选、全体友方和全体敌方；操作可新增、编辑、删除、上下移动。当前节点切换时编辑表单重新初始化，方案中的已添加操作保持稳定 ID。所有操作拥有可检查的来源 ID。

Preset 仅填表，点击「添加效果」后才进入计划。翁瓦克只在战斗开始且所选目标面板速度至少 120 时可填入 40% 提前；风套为单体 25%；舞舞舞叠影 1–5 为全体友方 16/18/20/22/24%。确认后都是普通 `advance`，没有装备标记进入引擎，也没有自动监听技能或再次触发。

## 未支持机制与下一轮候选

未支持多波次、额外回合、阿哈时刻、卡厄斯兰那特殊倒计时、跨波次继承、技能自动执行、终结技/能量/战技点、伤害及敌人 AI。不提供任意 AV 节点、拖拽、保存、分享、导入导出。刷新或语言切换的完整页面导航会清空方案。

所有自然行动使用固定的回合结束前窗口；不声称模拟了真实战斗的每种技能插入窗口。立即行动只改变待行动单位行动条，不创建特殊额外回合。手动敌人的基础与面板速度都取其填写速度。

下一轮 UI 可讨论：给重复角色和手动单位更醒目的站位身份、缩短窄屏配置到结果的滚动距离、强化操作目标与 Buff 实例的可读性、增加列表内的队列状态检查入口。均不改变本轮已经测试的数学、排序、锚点和 Buff 生命周期。
