# 排轴模拟器 UI Polish Round 1

日期：2026-10-12。实施于本地 `develop`，依据 `Action-Simulator/Overall-UI-Polish-01.md`。本轮仅修改 HSR-Database，未提交、推送、合并或远端部署；调度、队列数学和目标资格继续以原有引擎为准。

## 1. 三栏 UI 与 SectionHeading

左侧保留四个既有角色槽位，使用 `SectionHeading level={2}` 分隔「我方队伍」和「推演范围」。删除角色选择后的速度初始化说明和折叠帮助中显然的操作描述；保留单波次、额外回合／技能／伤害／装备自动触发未支持以及刷新后方案不保留等限制。输入范围、速度初始化、选择器与资源加载未变。

中间序列栏内部增加同级「行动序列 / Action Order」标题。未来行动／当前队列改成同一容器内的两段等宽控件，使用原有 `aria-pressed` 按钮、键盘激活与可见焦点。没有改变队列游标和两种视图的数据语义，也未新增滚动区域或修改总体响应式断点。

行动卡继续纵向独立排列，弱化普通边框，选中卡保留克制的金色强调。无附加信息的卡片保持紧凑；有操作或受影响历史时才增加底部内容。系统节点、事件虚线边框及 ParticipantIcon 的图片失败回退继续保留。

## 2. Inspector 信息层级与组件组织

当前节点标题由名称、辅助自然行动次数和右侧累计 AV 构成。战斗开始明确显示 `0.00 AV`；Scheduled Event 只显示名称与 AV；不可达节点不补造数值。名称在桌面省略并提供完整 title／可访问区域名称，极窄容器允许换行；AV 保持完整显示。

`OperationList` 使用 `SectionHeading level={3}` 展示「已配置操作」，Inspector 使用相同组件展示「添加操作」，两个区域间距大于普通字段间距。没有新增大型 Card 容器或另造标题分割线。

操作列表过滤所有空阶段；只有两个阶段均非空时才显示轻量阶段标题，不显示空计数。卡片突出效果名称和主要参数，头像与时机降低视觉权重；编辑、组内上下移动、删除继续使用原回调及阶段内移动算法。内部 ID 只保留在测试／原始数据属性中。

创建 Tab 缩短为「效果／行动单位」，共享容器并保留 tablist、tabpanel、roving tabindex、左右／Home／End 导航和焦点。两个表单继续独立挂载，切换 Tab 不销毁草稿；切换节点仍按原锚点重建。新建标题缩短为「新增」，编辑标题与保存按钮明确区分编辑状态。保留原有打开、取消、提交、错误反馈与焦点恢复行为。

效果类型保留两列较强选择；结算时机使用紧凑等宽分段，速度方式、持续方式及参与者次要参数使用较弱的中性选中态。目标头像 Grid、装备预设、有限／无限／倒计时持续方式和稳定实例身份未改变。

## 3. AV 统一格式与逐项操作标签

Presentation 的共享 `formatAV(value, locale, signed?)` 使用 `Intl.NumberFormat`，最少／最多两位小数。通过 Intl 实际显示的数字部分判断舍入后是否为零，再消除负零；带符号变化量使用 `signDisplay: 'exceptZero'`。累计、推进、剩余 AV、Inspector、队列进度及变化标记均复用它，并采用 `tabular-nums`。

SPD、百分比、编辑输入及原始 `data-*` 数值不强制采用 AV 精度。没有将格式化字符串或两位小数写回引擎。

删除混合／同类操作计数摘要及其类型。`orderedCardOperations` 对普通行动按行动前、动作后投影，阶段内保留配置顺序；系统和触发节点直接保持有序列表。每条操作独立显示一个可换行标签，复用共享操作标题，时机通过 tooltip 表达。标签不另设编辑入口，仍点击整张卡片选择节点。

中文／英文新增 7 个消息键，调整新建效果状态文字，删除 6 个无引用的速度说明、帮助和汇总消息；最终 571 条双语消息通过校验和编译。没有新增可变 locale 状态或改动路由语言选择。

## 4. 行动变化 Trace 模型与生命周期

新增 `ActionChangeTrace` 保存：operation ID、源锚点与阶段、目标待行动锚点、操作结算时累计 AV、提前／延后类型、实际前后 AG、当时有效 SPD、原始 ΔAV 和零 AV 实际插队标志。

每个运行参与者持有 `pendingActionChanges`；`NodeRecord.actionChanges` 保存到达该行动前的历史，`QueueEntry.actionChanges` 保存快照时已发生的历史，Presentation Adapter 将相应数组交给 ActionCard。`SimulationPlan` 不含 Trace，不增加持久化格式、通用日志或额外状态机。

执行器从原有排序结果取得目标，在原有候选状态中记录实际变化；候选通过 `assertState` 后才随操作状态提交。缺失／非法目标、被排除的行动前自身目标不产生记录；失败候选不会泄漏到输入。步进失败仍不发布部分节点或快照。

目标到达队首时复制其历史到 record，并在克隆后的运行状态清空；行进到下一回合不会继承旧记录。动作后自身效果使用已经递增的 turn 生成下一锚点。动态创建初始化空历史；有限 Actor 离队和一次性事件触发后随实例清理。身份按稳定 Participant ID 和 NodeAnchor 关联，不按名称或队列位置绑定。

运行克隆及队列快照独立复制 Trace 和锚点，旧快照不会被后续结算修改。编辑早期操作触发完整重算，历史随模拟重新生成。表单预览仍在独立克隆上重放，不写入实际结果。

未来视图展示该实际行动到达前的历史；当前队列仅展示所选快照时已经提交的影响，不从最终未来记录补入尚未发生的操作。

## 5. 差值定义与边界

每次变化使用完整精度计算：

```text
ΔAV = (AG_after − AG_before) / SPD_at_operation
```

例如剩余 AG 为 6000、100 SPD 的目标被 80% 提前到下限 0，记录的是 `−60.00 AV`，不是理论 `−80.00 AV`。之后速度变化不重算这条历史；它不是无效果方案与当前方案之间的最终时间差。

零 AV 再次有效提前仍执行既有批次优先级刷新。Trace 比较操作前后真实队列位置，只有目标实际向前移动时标记「↑ 插队」。已经在队首的刷新、同序群体刷新、0% 操作不会产生虚假插队提示。零数值记录仍在数据层保留，UI 隐去没有数值变化且没有实际插队的记录；不出现 `−0.00 AV`。

多次提前、延后分别保留并展示；与速度修改交错时，每次使用各自操作时的速度，不相加成单一方向。单次群体批次、群体原顺序和后拉先动沿用原逻辑。

本轮 Trace 只覆盖 advance／delay。立即行动保留独立机制和配置标签，不被转换成 100% 提前，也不显示推测出来的变化历史。

## 7. 已知边界与后续人工验收

方向标记是操作瞬时变化的解释，不能当作最终提前时间或反事实结果。没有动画、历史面板、技能专用自动判断或立即行动 Trace。

本轮真实浏览器覆盖 Chromium 桌面和移动模拟；未验证其他浏览器及实机触控。人工可继续检查自用字体／缩放、特别长的倒计时名称、多个重名召唤物和大量标签换行。录入真实角色配置后，应核对每条操作的目标和阶段；本轮仍是通用排轴工具，不会自动计算角色技能。

所有变更保留在 develop 工作区；两个只读上游的开始／结束 Git 状态均为空。截图、精确对照夹具和本地日志仅保存在仓库忽略目录中，不进入计划或正式源数据。
