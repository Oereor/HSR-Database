# 排轴模拟器 Phase 3A：Inspector 与动态参与者创建

日期：2026-10-12。本轮在 `HSR-Database` 的 `develop` 分支实现，未提交、推送、合并或部署。本文记录本轮实现与验证结果；现行代码和架构规范优先于阶段报告。

## 1. 最终组件结构

右侧仍按「当前节点 → 已配置操作 → 操作编辑区域」组织，不改变三栏宽度。

| 组件 | 职责 |
| --- | --- |
| `Inspector.svelte` | 两个 Tab、编辑入口、统一保存／删除、编辑卡选中态及 Tab 键盘导航 |
| `OperationList.svelte` | 单一有序列表、窗口分组、按操作位置取得目标快照、上移／下移／删除 |
| `EffectForm.svelte` | 四类普通效果的草稿、阶段、目标、参数反馈和提交 |
| `ParticipantForm.svelte` | Actor／战斗事件草稿、创建及已有操作编辑 |
| `PresetSection.svelte` | 翁瓦克、风套、舞舞舞三个预设，选择后仅填充效果草稿 |
| `ParticipantIcon.svelte` | 现有图片及通用单位／计时器图标，图片加载失败时回退 |

原 `EffectEditor.svelte` 已删除，不保留兼容 Adapter。两种表单提交同一个 `EffectOperation` 模型，Inspector 调用既有 `saveOperation`，再由 ActionPlanner 更新唯一的 `events` 并完整重算。没有新增第二套已提交操作列表。

`participant-config.ts` 只负责草稿初始化、字段解析、保留原操作身份及构建创建操作；最终结构与阶段合法性仍由 `validateOperations` 验证。没有在组件中重算队列、推导 AV 或实现生命周期。

## 2. Tab 与编辑流程

默认选中「添加效果」，另一个入口为「添加行动单位」。两个表单在切换 Tab 时保留各自的未提交草稿，隐藏的面板不会参与键盘焦点遍历。提交或取消只清理对应草稿；选择其他节点通过现有稳定锚点的 keyed Inspector 重新初始化，两份草稿均清空。

点击已有卡片会打开对应 Tab，并载入该操作。普通效果和创建操作都支持原位编辑、排序和删除；倒计时持续速度效果仍仅展示、排序、删除，其编辑留待 Phase 3B。取消返回对应新增按钮，不修改计划。

Tabs 使用 `tablist`、`tab`、`tabpanel`、`aria-selected` 与关联 ID；只让当前 Tab 进入 Tab 序列，左右方向键循环切换，Home／End 跳到首尾。编辑时将焦点移到表单标题；Pill、目标头像和列表控件保留原生按钮语义与焦点样式。

Actor 节点显示行动前／动作后窗口。开始节点及触发节点只有一个操作列表，也不显示阶段选择。组内移动仍使用 `moveOperation`，阶段改变仍追加到目的窗口；UI 分组不改变引擎执行顺序。

## 3. Actor 与战斗事件表单

Actor 可以填写自定义名称、我方／敌方阵营、可选类别、基础速度、面板速度及最大行动次数。类别覆盖普通、自定义、召唤物、忆灵、敌人，仅保存元数据，不产生角色技能或主人关系。类别可以取消选择。

新建默认 Actor、我方、自定义类别、基础与面板速度均为 100。两项速度独立编辑。最大行动次数留空表示无限；填写时须为正的安全整数。名称须去除首尾空白后非空，速度须为有限正数；错误显示在对应字段并保留草稿。

战斗事件只显示名称和速度，默认速度 100，使用已有的一次性触发生命周期。Actor 字段及草稿中的行动次数不会混入事件定义。新建两种类型都省略 `initialAG`，使用引擎默认 10000；未增加高级 AG 输入或资源选择器。

输入变化不更新计划。提交先解析完整草稿并验证操作，通过后才统一保存；失败不发布操作或参与者。

## 4. 队列、目标选择与节点时点

创建操作使用既有 `spawnParticipant` 路径，重新推演后在「未来行动」和「当前队列」中显示动态参与者。两种视图沿用携带 Participant 信息的投影和稳定锚点；点击动态 Actor 的自然回合或事件触发节点，都能继续配置效果或创建其他参与者。

表单候选和操作卡上的群体目标均通过 `previewOperationState` 重放当前阶段中该操作之前的配置。新增效果在当前窗口末尾预览；编辑效果在原位置预览。因此先创建再作用可以选择新单位；把效果移到创建之前，该单位不再可选，已有失效引用保留并诊断。

新增 `operationTargets` 是目标展示投影：不从定义目录补齐未来或已离队的单位；同时排除当前已经进入触发节点的战斗事件。该事件仍存在于引擎状态中供诊断使用，但已退出可作用的队列。Actor 的行动前速度效果资格和既有 active-target 机制保持不变。

`selectableTargets`／`validTargetSelection` 继续负责资格：Actor 支持通用效果；尚在队列中的战斗事件仅接受显式单目标提前／延后，不能与其他单位混选，不接受立即行动或速度效果。全选和装备预设只选择 Actor。

无真实 before-effects 状态的超预算或不可达节点，候选为空，不再回退到当前队列制造另一时点的可用目标。已有配置仍可打开、删除或修复；扩大推演范围使节点可达后，会恢复真实候选。目录仅供名称／图标显示。

## 5. 稳定身份与删除

创建操作编辑始终保留原 operation ID，因此由 `spawnedParticipantId` 派生的实例身份不变。修改名称、速度、阵营、类别或行动上限会重算队列，但后续事件仍按原实例锚点关联。已有 `iconUrl` 和 `initialAG` 在未开放对应输入时保留。

编辑已有创建操作时禁用 Actor／事件类型切换，草稿构建函数也拒绝生命周期种类变更。需要变更种类时删除后重新创建，使用新操作 ID，避免自然行动锚点被解释为事件触发节点。

删除只移除该操作，再完整推演；没有清理或重新绑定其他事件。后续不可达配置仍由原有诊断、节点入口和删除入口显示。取消编辑不会触发保存。

## 6. 卡片、图标与文案清理

创建操作卡区分创建行动单位和创建战斗事件，显示名称、面板速度／事件速度以及无限／有限行动次数／一次性摘要，开放卡片点击编辑。没有显示操作 ID 或实例 ID。事件序列卡使用轻量虚线边框和计时器回退图标，不显示回合编号。

ActionCard 现在优先使用投影的 `iconUrl`，再使用初始角色头像。ActionCard、目标 Grid、操作卡统一使用 ParticipantIcon；缺少图片或加载失败时不会产生破图。操作目标头像保留可访问名称。

删除 Inspector 的开战流程段落、重复操作计数、每个空分组反复出现的说明及无限持续帮助段落。次数／持续输入用 `∞` placeholder 表达留空语义；仍保留验证反馈、不可用目标提示和不可达诊断。效果表单打开时隐藏重复的新增入口；同时移除队列速度状态中的内部 modifier ID。

清理旧创建操作只读条件、失效样式和旧组件结构断言。页面折叠帮助也同步缩短，并删除“倒计时尚不支持”的过期限制。

## 7. Site Message 调整

中英文消息均维护，所有组件使用显式 locale 调用，不增加可变 locale 状态。总消息数由 542 调整为 564。

新增 26 个键，涵盖添加／编辑／保存参与者、类型与阵营、五类类别、行动次数及摘要、一次性摘要、两类创建标题、编辑区域可访问名称、不可用目标、名称／速度／次数错误和已移除单位标签。名称和速度字段复用既有 `planner_name`／`planner_speed`。

调整 `planner_configured_effects`、`planner_effect_count` 为通用操作语义；缩短 `planner_configuration_readonly`，仅说明倒计时速度效果暂不可编辑；同步调整 `planner_spawn_participant`、`planner_scheduled_event` 和折叠帮助／限制。

删除无引用键：`planner_start_window`、`planner_duration_help`、`planner_no_effects`、`planner_unknown_unit`。后者由不显示内部 ID 的 `planner_removed_unit` 替代。

测试不锁定上述生产文案。预设双语验证继续使用合成消息，行为测试以数据、身份、结构和状态断言为主。

少量新增单测覆盖草稿校验、独立速度、隐藏字段、稳定身份、有限行动及删除后不可达配置；验证排序前后的真实候选和触发事件离开目标集合。既有引擎测试继续保护双窗口、群体批次、零 AV 插队、速度效果、一次性事件和三个预设。

SSR 测试将原创建操作只读要求改为可编辑要求，保留触发节点单窗口和逐操作群体目标投影，并新增无上下文时不从目录伪造目标的保护。预设组件测试改为直接验证拆出的 PresetSection，减少对旧协调组件结构的依赖。

新增浏览器场景覆盖创建召唤物并在其节点添加效果、编辑速度和次数、取消、删除后保留不可达配置；事件触发后立即行动和两种视图；独立草稿、Tab 键盘、参数错误及先作用后创建。已有缺图和超预算测试按新语义调整。没有重复为引擎数学建立大量测试，也未运行全站回归或远端验证。

## 9. 待浏览器验收及人工步骤

当前不能声称鼠标／键盘实际交互、移动端布局或图像加载失败路径已通过浏览器验收。准备项目所需 Chromium 后，使用本地最新构建运行：

```sh
PLAYWRIGHT_REUSE_BUILD=1 pnpm exec playwright test tests/e2e/action-planner.spec.ts \
  --project=desktop-chromium --project=mobile-chromium --reporter=line
```

人工补验：

1. 战斗开始 → 添加行动单位 → 创建召唤物 → 选择其自然回合 → 动作后添加提前效果 → 回到创建节点编辑速度／次数 → 确认新顺序及原节点配置 → 删除并确认不可达配置仍在。
2. 创建 90 SPD「协奏」 → 选择触发节点 → 配置知更鸟立即行动 → 确认后续零推进 AV 行动及事件只有一次触发。
3. 同节点创建后再施加效果；交换顺序后目标不可用且出现诊断。验证事件不能混选、不能接受立即行动或速度效果。
4. Tab 左右／Home／End、草稿切换与取消、两个语言入口、窄屏无横向溢出、两种序列视图和真实角色／通用图标回退。

## 10. Phase 3B 接入点

倒计时持续仍使用既有 `SpeedDuration` 联合类型和统一生命周期。后续可以在 EffectForm 内扩展持续方式及草稿解析，并解除当前仅针对 `duration.kind === 'countdown'` 的参数编辑限制；无需增加操作列表、队列或新的实例身份规则。

OperationList、ParticipantIcon、真实操作位置预览和稳定节点选择已经可以复用。真实敌人／召唤物资料选择、主人关系、角色专用技能、额外回合、多波次、保存分享及复杂拖拽均未加入本轮。
