# 排轴模拟器 Phase 3B：速度效果关联倒计时 UI

日期：2026-10-12。实施于 `HSR-Database` 的 `develop`，未提交、推送、合并或部署。本文记录本轮实现与验收边界，领域机制仍以代码及现行架构规范为准。

## 1. 持续方式交互与草稿

EffectForm 的速度效果新增「按回合数／按倒计时」Pill，按当前选择显示对应字段。默认按回合数、2 回合；倒计时名称默认空，速度默认 70。切换方式保留两组未提交输入；只解析和提交当前方式，隐藏输入不会造成错误或混入操作。

| 表单配置 | `SpeedDuration` 映射 | 校验 |
| --- | --- | --- |
| 正常回合数 | `{ kind: 'turns', turns: n }` | 正的安全整数 |
| 回合数留空 | `{ kind: 'turns', turns: null }` | 无限持续，不使用大数占位 |
| 倒计时名称／速度 | `{ kind: 'countdown', name, speed }` | 名称去除首尾空白后非空；SPD 为有限正数，可为小数 |

新增 `speed-duration-config.ts`，提供默认值／编辑回填及纯草稿解析。字段错误在表单中关联到相应输入，复用已有名称、速度和回合数错误消息；最终操作继续经过 `validateOperations`。不在组件中计算 AG、AV 或速度状态生命周期。

草稿与已保存操作保持分离。取消不更新计划；Inspector 两个 Tab 之间继续分别保留草稿，切换节点则清空。有限、无限和倒计时三种形式均可通过已有速度效果卡进入编辑。

## 2. 关联倒计时生成与触发

提交仍然只有一条标准 `addSpeedModifier`，没有另外保存 `spawnParticipant`。复用原 `operations.ts` 的原子创建路径：为每个有效 Actor 创建独立速度实例，并为整条源操作创建一个共享 Scheduled Event，生命周期引用其派生实例 ID。

触发沿用原引擎顺序：先移除关联速度状态并验证有效速度，再执行触发节点的有序操作，最后移除事件。剩余 AG 不重置；后续 AV 使用恢复后的速度。事件不递减其他 Actor 的回合持续状态，也不生成下一次自然行动。

自动倒计时和手动创建的战斗事件使用相同的序列卡、计时器图标、稳定触发锚点和单窗口 Inspector。用户可以在自动倒计时的触发节点继续配置立即行动等通用操作。

本轮没有修改 `types.ts`、队列数学、目标资格、操作执行器或引擎调度。

## 3. 编辑、删除与持续方式切换

删除 EffectForm 中对倒计时速度效果的提前返回，以及 EffectCard 的只读禁用条件。编辑恢复目标、阶段、速度修正类型／数值、持续方式、倒计时名称和速度。

保存沿用原 operation ID 与既有 `saveOperation`。因此修改名称、速度、修正值或合法目标后，`countdownParticipantId(operationId)` 不变；配置在该触发锚点上的后续操作仍关联同一实例。取消只丢弃草稿。

从回合切到倒计时后，使用源操作派生身份创建事件；切回有限／无限回合后，不再生成该倒计时。删除源速度操作也会让对应速度实例和事件都不再生成。后续触发配置由原有不可达事件机制保留并诊断，不删除、不改绑；在同一源操作上恢复倒计时持续后，可以重新到达原触发锚点。

真正删除源操作后再新建使用新 ID，不按名称恢复旧实例。没有新增自动迁移系统或保存格式。

## 4. 目标选择与同名实例

按已确认偏好，仅重名参与者显示「名称 · 序号」。新增 Presentation 的 `participantLabels`，从完整定义目录按稳定 ID 排序计算同名组内序号，不使用当前 AV、队列位置、回合编号或名称作为目标身份。

显示标签通过可选 `ParticipantLabels` 接口传给目标 Grid、预设目标、操作摘要、节点标题、诊断／不可达入口和两个序列视图。单独使用组件时仍可回退到原名称。标签依赖显式传入响应式摘要和标题计算，添加同名实例后已有卡片也会更新。

队列重排不改变标识。新增、删除或改名改变重名集合时，标识可以重新计算；只剩一个同名实例时恢复无序号显示。操作目标始终保存真实 Participant ID，显示标签不进入计划数据。

真实候选仍由 `previewOperationState`、`operationTargets` 和共享 `targeting.ts` 判断。定义目录只用于显示，不允许未创建、已离队或正在触发的事件成为虚假候选。倒计时仍只能显式单目标提前／延后，不能与其他单位混选，不接受立即行动／速度效果，群体效果和全选不包含事件。

未增加目标分组、筛选器或依赖关系管理面板。

## 5. 速度卡与队列状态展示

EffectCard 按持续方式显示有限回合、无限或「至倒计时名称 · SPD」摘要；名称取共享显示标签，因此同名倒计时也可区分。卡片可以编辑、排序和删除，不展示内部 ID 或生命周期枚举。

ActionCard 的队列速度明细通过状态的关联 Participant ID 查找倒计时显示名称。没有显示目录标签时保留通用倒计时文字回退。倒计时累计／推进／剩余 AV、速度和事件样式沿用 Phase 3A，无普通自然回合编号，也不新增解释性段落。

## 6. Site Messages 与清理

新增 7 条双语消息：持续方式、按回合数、按倒计时、倒计时名称、倒计时速度、至指定倒计时、同名实例标签。所有调用显式使用页面 locale，没有新的语言状态。

删除无引用的 `planner_configuration_readonly`。名称／速度错误复用既有消息，回合输入继续使用 `∞` placeholder。保留 `planner_until_countdown` 作为缺少显示标签时的状态摘要回退。

清理旧的独立 `turns` 表单状态和内联解析，改为持续草稿；删除倒计时只读判断及失效提示，不增加兼容 Adapter。消息总数从 564 变为 570。测试不固定生产文案，重名投影使用合成标签断言。

## 7. 场景验证结果

| 场景 | 已完成的确定性证据 | 浏览器状态 |

| 编辑名称／速度、切回回合和删除 | 同一源 ID 的触发配置继续执行；有限／无限持续及删除不留下倒计时；不可达配置保持原锚点 | 新增编辑、取消和模式切换流程，未运行 |

以上“流萤式／知更鸟式”仅表达用户自行配置的通用操作，没有角色技能硬编码；确定性机制测试使用合成配置，不伪造官方角色数值。不能将机制单测或 SSR 渲染等同于实际游戏机制或浏览器交互验收。

## 9. 未完成验收与人工步骤

准备当前项目所需 Chromium 后，使用本地构建运行：

```sh
PLAYWRIGHT_REUSE_BUILD=1 pnpm exec playwright test tests/e2e/action-planner.spec.ts \
  --project=desktop-chromium --project=mobile-chromium --reporter=line
```

人工确认：

1. 选择流萤或创建自定义 Actor，配置固定速度 +60／完全燃烧／70 SPD，再配置 100% 提前；确认事件一次触发且到期恢复速度。
2. 在正常行动节点对倒计时单目标延后 10%，确认结束时间和关联状态同步延长；群体提前不包含倒计时。
3. 在触发节点添加立即行动，回到源效果修改名称和速度；确认触发节点配置保持身份。再切回有限／无限回合或删除，检查不可达配置保留。
4. 给两个 Actor 同时加速并共享一个倒计时，逐步观察两项状态同时结束且其他状态保留。
5. 同名 Actor／倒计时的目标标签、操作卡、标题及两种序列保持一致；配置只作用于选中的实例。
6. 中英文输入、持续方式 Pill 的键盘激活、取消／Tab 草稿保留、错误反馈和窄屏无溢出。
7. 回归独立 90 SPD 协奏事件与知更鸟立即行动，确认没有自动屏蔽自然行动的角色逻辑。

## 10. 下一轮边界

本轮没有进行整体三栏 UI Polish。后续应在真实浏览器补验后，再集中处理长名称、目标密度、表单留白和窄屏布局；本轮没有新增独立滚动区域或复杂动画。
