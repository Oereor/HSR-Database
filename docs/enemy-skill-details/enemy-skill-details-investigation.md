# 敌方技能详情：代表性数据第二轮调查

调查日期：2026-09-29。主证据为本地 `TurnBasedGameData` 的 `8b178dd486`；网站仓库为 `fa291a045c`。本文中的百分比是 **Ability 的伤害倍率或配置的基础概率输入**，不是对具体角色的最终伤害或最终命中率。报告只研究静态敌人详情；[前次审计](../combat-simulation/combat-simulation-feasibility-audit.md)的模拟器路线已经搁置。置信度“高”表示配置中的引用与任务可直接闭合，“中”表示需解释表达式或条件，“低”表示仅有文案或部分引用。

证据路径均相对于 `TurnBasedGameData/`：`ExcelOutput/MonsterConfig.json` 简写为 MC，`MonsterTemplateConfig.json` 为 MT，`MonsterSkillConfig.json` 为 MS，`MonsterStatusConfig.json` 为 ST；CC 是 MT 的 `JsonConfig` 所指 `Config/ConfigCharacter/Monster/*_Config*.json`，AB 是同怪物前缀的 `Config/ConfigAbility/Monster/*_Ability*.json`。所有 ID、哈希均按十进制字符串记录。UI 示例中的“ATK”只表示 `DamageByAttackProperty.AttackProperty.DamagePercentage` 的攻击属性倍率输入，不包含防御、抗性或暴击计算。

## 1. Executive Summary

**静态详情扩充可行，但不能给每个技能强制填一个倍率。** 十个要求调查的 Monster ID 均存在，`2012010` 在当前中文 TextMap 中确为“入魔机巧 • 灯昼龙鱼”。单体、群攻、主/邻位、左右横扫的数值可以从 MS 参数经 CC `DynamicValues` 到 AB 伤害任务闭合。`3003051` 的两种 DoT 状态可闭合名称、类别、基础概率和回合型期限；`401401207` 的弹射还有可追溯的每次倍率与循环次数。重复顺序伤害任务（如卡芙卡扩散、裁定者重击）则不能仅凭一个参数声称整技能总倍率。召唤对象的 ID 和本地化名称可解析，但条件下的实际数量通常不固定。

首版建议只上线**明确的伤害倍率分目标行、基础概率、已核实的状态身份与简单回合期限、召唤候选链接**；按 Monster ID 计算有效参数。复杂共享伤害、条件倍率、自损、行动条数值和韧性数值先不展示。`4064012` 的 `DamageStance` 证明怪物自身/召唤物确实可能成为韧性伤害目标，但单位与公式未达到安全展示程度。完成本报告后可以开始一个受限的生产实现阶段。

## 2. Scope and Product Decisions

- 保留现有技能类别（单攻、群攻、锁定、横扫、分摊等）和伤害属性；不重新分类。
- 候选补充：分目标倍率、弹射每次倍率与次数、仅对可有韧性的目标有意义的韧性伤害、状态身份/类别/期限/基础概率、召唤单位引用。
- 基础概率就是配置 `Chance` 输入。例如 `1.2` 可写“120% 基础概率”；不计算效果命中/抵抗后的概率。
- AI 选技、权重、回调名与顺序、Camera、动画、音画及表现几何仅可作解析证据，均不进入浏览器领域模型。现有官方描述保留原文，新增事实作为独立补充。

## 3. Existing Enemy Skill Pipeline

`scripts/data/domain/enemy.ts` 用 MC/MT/MS 构建 `EnemySkillDomain`，目前保留 ID、名称/描述文本源及插值参数、kind/tag、元素、阶段与额外效果 ID；它不读取 CC/AB/ST，也不保留伤害任务、概率或状态期限。`scripts/data/projection/enemy.ts` 把文本投影为 `EnemySkill`；`src/lib/domain/neutral.ts` 与 `types.ts` 分别定义中性/本地化类型。`src/lib/domain/enemy-view.ts` 将技能定义按 **Skill ID 去重**，而 `EnemyDetailPage.svelte` 切换 Monster 变体，技能卡却使用全局 `skillDefinitions`；因此同一 Skill ID 在变体中改变参数时，当前卡片结构无法呈现变体特有详情。`EnemySkillCard.svelte` 现有标题、tag、元素、官方描述和额外效果，适合在描述下添加紧凑的补充行。

页面已有 `EnemyDetailPage.svelte` 的召唤区与 `CompactEntityCard.svelte`，并有 `EnemySummonReference` 的 ID、名称、图片和本地化链接投影。技能内召唤应复用这条投影/卡片路径。构建输入 `scripts/data/source-requirements.ts` 已包含 CC/AB 怪物目录及 MC/MT/MS，**未包含 ST**；正式增加状态身份前需把 ST 纳入构建输入和源校验。仍应使用现有 TextMap 解析器，并维持中性域→中英投影→生成数据的边界。

## 6. Damage Multiplier Findings

| 形式 | 实证 | 可展示程度 |
|---|---|---|
| 单体 | `102201001` 的 `3 → DamagePercentage(AbilityTargetEntity)` | 300% ATK，直接 |
| 主/邻位 | `100203001` 的 `1.3/1`、`401401202` 的普通分支 `1.6/1.4` | 两行，按目标角色 |
| 群体 | `200401003` 的 `2.5 → AllEnemy` | 全体 250% ATK |
| 横扫 | `401301001/002` 的同一 `2.8` 分别到左/中/右 | “每个命中目标 280% ATK”；无需新技能类别 |
| 弹射 | `401401207` 的动态每次伤害与循环 | 每次倍率＋次数；不拆成逐击列表 |
| 敌方侧伤害 | `201201002` 的 `AllTeammate` 40% | 必须记录相对施术者的目标侧 |
| 条件/分摊 | `401301004` 四哈希表达式；`401401210` 动态值 | 只保留官方描述的定性事实，暂不输出固定倍率 |

因此伤害应是**可选数组**，每项表示目标角色、倍率与 ATK 缩放；不能是整个技能的单个 `damageMultiplier`。条件倍率要在能可靠解释条件后才进入数组。普通 `DamageByAttackProperty` 的 `DamagePercentage` 是缩放输入，不包括最终伤害公式；重复任务或多击不得无条件相加。

## 7. Bounce Findings

`401401207`“那矛尖刺入天帷”对应 CC `Skill04` → AB `Monster_W4_Nikadory_00_Skill04_Phase02`。`Skill04` 参数 `p0=0.9,p1=5,p2=10`。普通分支先把 `p0` 放入 `Skill04Damage`，各次伤害从该动态键读取，故**普通分支每弹 90% ATK**；存在 `FT_SpecialAction` 分支改写该值，不能笼统声明所有状态都为 90%。

首段 `LoopExecuteTaskList.MaxLoopCount=1`，其 `Retarget` 用 `TauntOrRandomEnemy`、`ByRandom=true`、`MaxNumber=1`；后段从 `Skill04 p1` 与固定 1 的减法表达式设置 `Skill04Count`，再用其作为循环上限。按表达式运算符及一首段加余下四段解释，**常规共 5 次**。`401401208` 对应 `Skill14`，改用同一 `Skill04 p2=10`，即强化分支共 10 次；因为这涉及运行时动态键，次数结论为中高置信，正式解析器需有 postfix 单元样本验证。

后续 `Retarget(AllEnemy)` 带“没有 `Skill04AlreadyAttack`”谓词、`ByRandom=true`、`MaxNumber=1`；被选目标加该标记。候选耗尽的失败分支改为无排除谓词的 `Retarget(AllEnemy)`，**因此目标可再次被选中**。未找到每个候选的显式概率/权重；`ByRandom` 不证明均匀分布。初段并非固定用户所选主目标；有嘲讽/随机目标别名。首版若要展示弹射，只写“普通分支每弹 90% ATK、5 次；强化分支 10 次”，并由人工核对特殊行动的展示条件；不宣称等概率。

## 8. Toughness Damage Findings

普通敌→玩家伤害的 MS `SPHitBase`（如 `102201001=15`）和 AB `SPHitRatio=1` **不产生有意义的玩家韧性展示**，因为玩家角色没有通常意义上的韧性条。`201201002` 是反例方向：死亡时 `DamageByAttackProperty.TargetType=AllTeammate`，会触及敌方侧单位，但任务未带可直接解释的 `SPHitRatio`，不能从 MS `SPHitBase=5` 单独推出 UI 数值。

`Monster_W4_Serpent_01_Ability_IF.json` 的 `IF_Return_Phase02.DamageStance` 指向 `Caster`；`IF_Passive`、`IF_DebuffListener`、召唤物 `IF_Summon_SpecialLimbo` 的 `DamageStance` 指向 `ModifierOwnerEntity`。这证明韧性伤害属于**具体效果及其目标**，不是技能顶层通用字段。部分 `StanceValue` 含参数 `48/1440` 和其他动态值，且 `DamageStance` 与 `SPHitBase/SPHitRatio` 并行出现，当前不足以确认 UI 单位。首版不显示韧性数值；未来只对确认目标可有韧性的自伤/友伤效果增加可选字段。

## 11. Variant Findings

以 `MonsterTemplateID` 聚合比较 MC 的 `SkillList`、`OverrideSkillParams`、`SummonIDList` 与 CC 路径。十组分别有 3/5/10/15/4/20/30/25/13/18 个 Monster ID 变体，**相同技能 ID 不保证相同有效倍率**：

- `406401201` 的 `OverrideSkillParams` 指向 `406401201` 并给首参数 `3.6`，基础 `4064012` 为 `4`；`406401204` 从 `6` 改为 `5.4`，`406401207` 从主/副 `12/4` 改为 `11/3.6`。`406401202` 等又更换召唤 ID。字段名在上游为混淆键，技能 ID 与参数数组的对应关系清楚，但覆写应用优先级仍需解析器测试。
- `100203026` 对 `100203001` 给出覆盖参数 `[1,1]`，基础是 `[1.3,1]`；同一 Skill ID 的主目标倍率不同。`401401202` 有指向 `401401210` 的覆写记录，但参数 `14` 与基础值相同；`100402017` 覆写三项攻击技能。
- `401301007/009` 保持相同技能列表，却把召唤物 ID 改为 `401201014/016`。`2012010`、`3003051`、`1022010`、`1002040` 的已检查变体在上述字段上相同；不能据此推断全游戏不变。
- Kafka 与杰帕德若干变体的 `OverrideAIPath` 不同，但 AI 非本产品模型；本轮只把它作为变体存在的旁证，不纳入详情字段。

**归属建议：技能执行定义可按 Skill ID/trigger 复用，展示数值与召唤引用必须按 Monster ID 的有效配置生成。** UI 当前仅按 Skill ID 去重的定义列表需要改为“选中 Monster ID 的详情”或等价的按 `(Monster ID, Skill ID)` 选择，以免基础版本数值错误地显示在强化版本上。CC/AB 若有独立路径/Ability 变体，也必须按该 Monster 的有效配置选取，不能只按模板名猜文件。

## 12. Proposed Minimal Domain Model

仅为下一阶段的 TypeScript 伪代码；不把哈希、回调或证据路径发送到页面。`ratio` 建议使用项目现有十进制字符串约定，格式化到百分比时再乘 100。

```ts
type EnemySkillDetail = {
  monsterId: string;                 // 有效参数归属
  skillId: string;
  damage?: Array<{
    target: 'primary' | 'adjacent' | 'all' | 'each-swept' | 'each-bounce' |
            'self' | 'enemy-ally' | 'marked' | 'other-marked';
    ratio: DecimalString;
    scaling: 'attack';
    toughnessDamage?: DecimalString; // 仅目标可有韧性且单位已核实时
  }>;
  bounce?: { count?: number };      // 与 each-bounce 伤害行搭配
  statuses?: Array<{
    statusId: string;
    kind: 'Buff' | 'Debuff' | 'Other';
    target: 'self' | 'primary' | 'adjacent' | 'all' | 'enemy-ally';
    baseChance?: DecimalString;
    duration?: { kind: 'turns'; value: number } |
               { kind: 'until-triggered' | 'until-removed' };
  }>;
  summons?: Array<{ monsterId: string }>;
  effects?: Array<{ kind: 'action-delay' | 'action-advance' | 'trigger-dot' | 'clear-dot' }>;
};
```

这是**可选且保守**的模型：未验证数值省略字段；不以 `null/0` 伪装未知。状态和召唤保留稳定 ID，名称从各 locale 的 TextMap/敌人投影取得；倍率、次数、概率与目标角色保持 locale-neutral。不能闭合 ST 的通用 modifier 可暂不生成 `statusId`，即便官方描述已有名称。`Other` 必须保留，不能强行分成 Buff/Debuff。若未来精确条件伤害要上线，应另扩展有证据的条件结构，首版不存内部谓词树。

## 13. Proposed UI Information Architecture

保持“名称＋现有 tag/元素 → 官方描述 → 细线/间距 → 补充事实行”。简单单体可一行“伤害倍率　300% ATK”；状态技能可两行“荒宴醉／欢宴罪：基础概率 100%”“持续 2 回合”；主/邻位用同一标签下两行；弹射用“每弹 90% ATK”“共 5 次”；召唤则在补充区放已有 `CompactEntityCard` 的小型链接。复杂技能只列可靠项，例如“伤害由目标分摊”“可能召唤：天谴斗士”，不显示尚未解出的计算结果。

小屏下标签与值可上下排列，长状态名自然换行；空详情块不渲染。详情始终可见，不再加内层卡片或披露控件。选中 Monster ID 后更新技能补充数据，官方描述仍可共享。

## 15. Unsupported / Unsafe-to-Display Values

- `102201001` 的延后输入 `0.5` 与 Kafka `-1` 均为归一化行动条值；没有安全的“行动值/百分比”UI 换算。
- `100204001` 的 `AddModifier.LifeTime=2` 与 `GlobalModifier.LifeTime=1` 冲突；`200401004` 期限还含固定 1 的表达式。两者均不称固定 N 回合。
- `401301004` 的 `12`、`401401210` 的 `14`、`300305105` 的 `1` 不是可直接展示的攻击倍率。前二涉及运行时动态值/分摊，后一用于触发 DoT。
- `401401207/208` 的特殊行动分支会改写每弹倍率；弹射目标随机权重、具体嘲讽优先级未证。普通分支值不能用于所有场景。
- MS `SPHitBase`、AB `SPHitRatio` 不应令普通敌→玩家技能出现“韧性伤害”；`DamageStance.StanceValue` 的显示单位和部分复杂表达式仍未证。
- `4064012` 与 `4013010` 的候选召唤数据不等于每次实际召唤数量。`MonsterStatusConfig.StatusType=Other` 不能自动标成 Buff。

## 16. Recommended Production Scope

**Ready now：**按 Monster ID 生效的直接/分目标 `DamagePercentage`（只接收可闭合、非重复顺序任务的固定倍率表达式）；已映射 ST 的状态 ID/类别和 `AddModifier.Chance` 基础概率；`3003051` 这类有明确回合结算点的简单 `LifeTime`；解析成功的召唤候选链接。输出时对条件分支保守省略，保留原文。

**Needs one more targeted investigation：**弹射动态键与 postfix 运算符的自动解析及特殊行动分支；通用 modifier 的身份/持续时间；`OverrideSkillParams` 的完整优先级与少量阶段样本；自伤/友伤的韧性单位。`401401207` 的 5/10 次可在报告中审核，首版上线前需以解析器固定样本校验。

**Defer：**通用多击分配、复杂分摊/吸收倍率、行动条数值、条件召唤数量、最终命中率、完整伤害公式、AI/回调和模拟器。

## 17. Recommended Next Implementation Plan

1. 在构建期扩展敌人解析：对每个 Monster ID 选择有效 CC/AB，解析 MS 参数及 `OverrideSkillParams`，只识别白名单中的简单伤害、状态和召唤任务；对未闭合的哈希/表达式输出构建审计而非猜值。将 ST 加入源输入契约。
2. 扩展中性 `EnemySkillDomain` 与 locale 投影：保留数字和稳定 ID 为中性数据，用既有 TextMap/敌人投影解析状态及召唤名称；生成数据只带第 16 节 Ready now 字段，不带 AB 原始树或来源哈希。
3. 使详情页按选中 Monster ID 取技能补充数据；在现有 `EnemySkillCard` 下加紧凑事实行，召唤复用 `CompactEntityCard`。保留官方描述、类别和元素，移动端无新增嵌套卡。
